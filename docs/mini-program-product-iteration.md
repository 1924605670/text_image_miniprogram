# 小程序测试版工作台迭代说明

## 产品定位

本次迭代把项目从单一文生图演示，扩展为“小程序测试版发布工作台”。核心用户是产品经理、开发、测试和运维，目标是让每个测试版本都能留下需求、开发自测、测试结果、发布记录和产品验收记录。

## 本期目标

- 产品经理可以创建需求，填写业务目标、功能范围、验收标准和目标版本。
- 需求必须确认后才能拆开发任务。
- 开发任务必须填写自测说明后才能提交测试。
- 测试通过后才能创建发布任务，测试失败会把开发任务退回开发中。
- 发布任务必须记录服务器部署结果和小程序测试版提交结果后，才能进入产品验收。
- 首页提供“发布流 / 图片生成”双工作区，保留原文生图能力。

## 体验设计

- 使用看板式四列流程：需求确认、开发自测、测试闭环、发布验收。
- 顶部指标展示需求、开发、测试、已提交测试版和已验收数量。
- 左侧表单专注产品规划，减少跳转和弹窗。
- 操作按钮只出现在当前状态允许的动作上，避免误操作。
- 视觉风格从演示页改为内部工具风格：浅灰底、白色工作面、状态色区分优先级和流程结果。

## 技术方案

- 新增独立 workflow domain，不侵入原图片生成 domain。
- 使用 SQLite 持久化需求、开发任务、测试任务、发布任务和验收记录。
- FastAPI 提供 `/api/workflow/*` 接口。
- 后端集中校验关键流转规则，前端只负责展示可用动作。
- Vanilla JS 渲染工作台，保持当前项目轻量结构。

## 测试策略

- Schema 测试：覆盖文本 trim 和必填验收标准。
- Store 测试：覆盖 SQLite 读写和跨任务关联。
- Service 测试：覆盖未确认不可开发、无自测不可提测、未提交测试版不可验收等规则。
- API 测试：覆盖从需求创建到产品验收的完整 happy path。
- 浏览器验收：本地打开 `http://127.0.0.1:8000`，验证工作区切换、全链路按钮、指标刷新和控制台错误。

## 发布状态

本仓库当前没有微信小程序工程目录、`project.config.json`、appid、上传私钥或 `miniprogram-ci` 脚本，因此本次无法执行真实微信后台“上传测试版本”。已完成的是应用内“测试版提交记录”和“产品验收流”。

真实上传测试版需要补充：

- 微信小程序项目目录和 `project.config.json`。
- 小程序 appid。
- 上传私钥或 CI 机器人配置。
- `miniprogram-ci` 上传脚本。
- 版本号、体验版描述和上传人配置。
