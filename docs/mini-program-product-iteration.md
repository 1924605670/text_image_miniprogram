# 小程序测试版工作台迭代说明

## 产品定位

本次迭代把项目从单一文生图演示，扩展为“小程序测试版发布工作台”。核心用户是产品经理、开发、测试和运维，目标是让每个测试版本都能留下需求、开发自测、测试结果、发布记录和产品验收记录。

## 本期目标

- 产品经理可以创建需求，填写业务目标、功能范围、验收标准和目标版本。
- 需求必须确认后才能拆开发任务。
- 开发任务必须填写自测说明后才能提交测试。
- 测试通过后才能创建发布任务，测试失败会把开发任务退回开发中。
- 发布任务必须记录服务器部署结果和小程序测试版提交结果后，才能进入产品验收。
- 首页提供“发布流 / 图片生成”双工作区，保留原文生图能力。

## 体验设计

- 使用看板式四列流程：需求确认、开发自测、测试闭环、发布验收。
- 顶部指标展示需求、开发、测试、已提交测试版和已验收数量。
- 左侧表单专注产品规划，减少跳转和弹窗。
- 操作按钮只出现在当前状态允许的动作上，避免误操作。
- 视觉风格从演示页改为内部工具风格：浅灰底、白色工作面、状态色区分优先级和流程结果。

## 技术方案

- 新增独立 workflow domain，不侵入原图片生成 domain。
- 使用 SQLite 持久化需求、开发任务、测试任务、发布任务和验收记录。
- FastAPI 提供 `/api/workflow/*` 接口。
- 后端集中校验关键流转规则，前端只负责展示可用动作。
- Vanilla JS 渲染工作台，保持当前项目轻量结构。

## 测试策略

- Schema 测试：覆盖文本 trim 和必填验收标准。
- Store 测试：覆盖 SQLite 读写和跨任务关联。
- Service 测试：覆盖未确认不可开发、无自测不可提测、未提交测试版不可验收等规则。
- API 测试：覆盖从需求创建到产品验收的完整 happy path。
- 浏览器验收：本地打开 `http://127.0.0.1:8000`，验证工作区切换、全链路按钮、指标刷新和控制台错误。

## 发布状态

本仓库当前没有微信小程序工程目录、`project.config.json`、appid、上传私钥或 `miniprogram-ci` 脚本，因此本次无法执行真实微信后台“上传测试版本”。已完成的是应用内“测试版提交记录”和“产品验收流”。

真实上传测试版需要补充：

- 微信小程序项目目录和 `project.config.json`。
- 小程序 appid。
- 上传私钥或 CI 机器人配置。
- `miniprogram-ci` 上传脚本。
- 版本号、体验版描述和上传人配置。

## 二期规划：版本验收工作台

二期目标是把一期的流程看板升级为“按版本验收”的工作台，让产品、测试和运维在提交测试版之前能判断版本是否真的可验收。

### 产品目标

- 支持按目标版本筛选需求、开发、测试、发布和验收记录。
- 每个发布单必须维护发布检查清单、服务器部署结果、小程序测试版提交结果、风险记录、遗留问题和测试入口。
- 提交测试版时要求服务器结果、小程序提交结果和发布检查清单全部完成。
- 验收驳回必须记录阻塞原因，方便后续复盘。
- 顶部提供版本验收态势：发布单数量、风险项、遗留项、验收阻塞和版本准备度。

### 设计原则

- 继续采用内部工具风格，优先信息密度、可扫描性和低学习成本。
- 版本筛选放在指标区下方，避免用户在四列看板里手动定位版本。
- 发布卡片突出“检查清单完成度”，风险和遗留问题用弱警示样式展示。
- 发布记录使用统一弹窗维护，减少卡片上零散按钮和重复输入。

### 技术实现

- `workflow_release_tasks` 增加 `release_checklist`、`risk_notes`、`known_issues`、`test_version_url` 字段。
- `workflow_acceptances` 增加 `blocker_notes` 字段。
- SQLite 启动时自动补列，兼容服务器已有数据库。
- `/api/workflow/board` 支持 `version` 查询参数，并返回可选版本列表。
- 后端集中校验提交测试版和验收驳回规则，前端只负责交互和展示。

### 测试验收

- Schema/Service 覆盖检查清单校验、版本筛选和验收驳回阻塞原因。
- Store 覆盖新增字段读写和 SQLite 兼容迁移。
- API 覆盖完整 happy path 与版本筛选返回。
- 前端本地浏览器检查工作台加载、版本筛选、发布记录弹窗和提交测试版按钮。

## 三期规划：真实微信测试版发布链路

三期目标是从“记录测试版提交结果”升级为“系统可触发并追踪真实微信测试版上传”。这部分依赖小程序项目目录、appid、上传私钥或 CI 机器人配置，当前仓库仍缺少这些生产要素，因此三期先完成设计和接口边界规划，不在二期硬编码未知项目。

### 产品目标

- 接入真实小程序工程和 `miniprogram-ci`，由发布单触发测试版上传。
- 上传后自动回填上传结果、版本描述、体验二维码或测试入口。
- 支持上传失败重试、失败原因归档和回滚方案确认。
- 增加多项目、多角色权限：产品、开发、测试、运维、管理员。
- 增加通知和审计：测试版提交、验收驳回、风险未关闭时通知负责人。

### 技术方案

- 新增微信上传配置：appid、项目路径、机器人编号、私钥路径、上传描述模板。
- 使用独立上传服务封装 `miniprogram-ci`，避免发布流直接依赖命令行细节。
- 上传任务异步执行并落库，保留 stdout/stderr 摘要、退出码、二维码产物路径。
- CI/CD 继续只更新后台服务，不覆盖服务器 `.env.local`、数据目录和其他服务。
- 权限和审计独立建表，避免和当前轻量 workflow 表强耦合。

### 里程碑

- 3.1：补齐小程序工程定位、appid、上传私钥和本地 dry-run 上传脚本。
- 3.2：后端上传任务服务和发布单一键上传接口。
- 3.3：前端上传状态、失败重试、二维码预览和通知记录。
- 3.4：多项目权限、审计日志和发布复盘报表。
